# Travel Memory 全页面移动端设计说明

本次输出依据当前仓库路由、页面组件和已实现功能整理。设计图 PDF 内只有页面 UI；本说明单独解释页面目标、信息结构和设计原因。

## 补充视觉基准

`设计图/` 目录中的 10 张独立 PNG 已确认为后续移动端优化的主要视觉基准。文件命名、页面对应关系和业务边界统一记录在 [`设计图/README.md`](设计图/README.md) 中。

真实业务、当前代码、数据安全和权限边界优先于视觉图；在不冲突的前提下，对应页面应优先靠近这 10 张图的布局、层级、留白与移动端交互。

## 全局原则

- 保留项目现有米白背景、深棕文字和陶土橙强调色。
- Travel Memory 是私人旅行记忆产品，不增加社交、分享、攻略、发现或 AI 改写。
- 旅行内六个一级页面继续复用 TripViewNav，移动端使用横向滚动。
- 自然日统一使用“第 N 天”，按旅行开始日期计算，允许跳号。
- 所有点击目标至少 44px，固定操作区处理底部安全区。
- 页面截图为 390px 宽移动端完整滚动页面；实际实现需同时回归 360、375、412、768 和桌面尺寸。

### 当前共享实现

- `UserMenu.vue`：统一桌面顶栏与移动端首页、收藏页的账号入口，包含头像、管理员入口、修改密码和退出登录。
- `TripContextCard.vue`：统一地图、收藏回看与同行者页面的旅行封面、标题、目的地和日期上下文。
- `TripViewNav.vue`：统一旅行内部六个真实页面入口，移动端保持单行横向滚动，不因屏幕变窄换行。
- `MobilePageHeader.vue`：统一独立页面返回、标题与右侧操作；创建旅行使用文字“保存草稿”，Memory 表单沿用同一语义。
- `mobile-reference.css`：只负责移动端视觉基准覆盖，不改变桌面业务布局和接口行为。

页面对齐时保留每个页面自己的职责：Timeline 是记录浏览，Journey 是沉浸阅读，Map 是空间画布，Recap 是真实统计，Companions 是同行称呼管理。共享导航不意味着把这些页面做成相同结构。

## 01 登录

**对应：** `/login`

保留项目现有的用户名、密码、登录和可选注册入口。移动端将桌面的左右双栏改为“旅行封面式品牌区 + 单列登录卡”，首屏即可完成输入和提交；品牌情绪存在，但不会抢占表单。

## 02 注册

**对应：** `/register`

完全按照现有字段设计：用户名、显示名称、密码、确认密码、注册码。使用单列连续表单，密码规则和首个管理员提示放在提交按钮附近；不增加手机号、短信验证码或邮箱等后端不存在的字段。

## 03 修改密码

**对应：** `/change-password`

突出“首次登录必须修改密码”的阻断性质。顶部说明原因，下面只保留当前密码、新密码、确认新密码三个字段，主按钮唯一，减少用户把它误解为普通设置页的可能。

## 04 账号管理

**对应：** `/admin/users`

将桌面双栏表单和列表重排为移动端摘要、创建入口和账号卡片。每个账号显示名称、用户名、角色、启用状态和改密状态；重置密码与启用/禁用保持为次级操作，避免横向表格。

## 05 我的旅行记忆

**对应：** `/trips`

首页只承担旅行入口。顶部保留 Travel Memory 与用户菜单，正文首屏突出“我的旅行记忆”和“新建一次旅行”；旅行卡片聚焦封面、标题、国家与城市、日期、真实统计和四类浏览入口，编辑、删除、新增记忆收进更多菜单。列表末尾保留“下一段旅程，正在路上”的轻量续写入口；页面使用克制的纸张纹理和邮戳装饰，不加入虚构旅行数据。

## 06 创建旅行

**对应：** `/trips/new`

移动端按照“封面、旅行标题、目的城市、日期、描述、笔记”的顺序组织。目的城市使用可搜索候选框作为主流程，选择候选后保存解析出的国家、标准城市名称和 WGS84 城市中心坐标；地图确认是可选辅助操作，搜索或地图不可用时仍允许只填写城市名称。页面保留现有旅行草稿和受保护封面上传，不要求一次填写完整。

## 07 编辑旅行

**对应：** `/trips/:id/edit`

保留当前封面预览、恢复自动封面、基本信息、未保存提醒和同行者管理入口。目的城市与创建页复用同一搜索和地图确认组件；手动改写城市名称会清除旧坐标，避免名称与定位错配。移动端先展示封面，再展示表单，保存与取消放在底部操作区，减少长表单往返滚动。

## 08 时间线

**对应：** `/trips/:id`

旅行封面用于建立上下文，TripViewNav 采用横向滚动；搜索和新增记忆紧邻内容区。Memory 按旅行自然日分组，保留原话、时间、地点、照片和收藏，卡片点击进入详情，管理操作不干扰阅读。

## 09 收藏回看

**对应：** `/trips/:id/favorites`

与时间线复用同一信息结构，但弱化旅行管理和新增入口，只展示已收藏 Memory。卡片更紧凑，取消收藏后可直接从列表移除，符合“以后再看”的轻量阅读场景。

## 10 旅程回放

**对应：** `/trips/:id/journey`

Journey 被设计为阅读模式而不是管理列表。顶部自然日标签使用中文“第 N 天 + 日期”，下方按照时间顺序展示地点、用户原话、照片和同行者；不生成标题、不改写文字、不常驻编辑删除按钮。

## 11 地图

**对应：** `/trips/:id/map`

地图占据主要画布，Marker、自然日标签和底部 Memory 卡片由同一个 selectedMemoryId 驱动。卡片只展示当前选中记忆，底部日期横向切换；Marker 按 Memory 时间顺序编号，连线只表达记忆先后，不代表真实导航路线。没有带坐标的 Memory 时，如果 Trip 已选择目的城市，地图以该城市中心作为温和的默认视野，但不伪造 Memory 点或路线。

## 12 旅行回顾

**对应：** `/trips/:id/recap`

只使用真实统计生成回顾：记忆数、照片数、收藏数、地点数、每日代表 Memory 和高频地点。移动端以摘要卡和横向每日卡片组织信息，不生成 AI 故事、情绪评价或虚假天气。

## 13 同行的人

**对应：** `/trips/:id/companions`

同行者是旅行内的称呼标签，不是账号。移动端先放同行者管理和添加入口，再按自然日展示带同行者的 Memory；停用和改名属于管理操作，历史 Memory 中的关联仍然保留。

## 14 新增记忆

**对应：** `/trips/:id/memories/new`

沿用当前照片上传、最多 6 张、主图、EXIF 时间与 GPS、草稿、地点选择和同行者逻辑。页面按照照片、原话、时间地点、同行者的自然顺序排列，底部主按钮固定但不遮挡内容。

## 15 编辑记忆

**对应：** `/trips/:tripId/memories/:memoryId/edit`

与新增页面共享视觉结构，但明确展示已有照片、排序和主图状态。继续保留“所有照片草稿在最终保存时统一生效”、草稿恢复和离开提醒，保存成功返回记忆详情。

## 16 记忆详情

**对应：** `/trips/:tripId/memories/:memoryId`

详情页以照片和用户原话为核心，随后展示旅行自然日、时间、地点、同行者和所属旅行。收藏、编辑与更多操作集中在顶栏或底部；上一段和下一段让用户连续阅读。

## 17 地点选择器

**对应：** `LocationPicker 全屏组件`

虽然不是独立路由，但在移动端表现为完整工作页面。Memory 使用地点模式，支持 POI 搜索、地图选点和自定义地点描述；Trip 使用城市模式，优先搜索行政区候选，地图仅用于确认大致中心。两种模式都只在点击确定后回写表单，取消不会改变原数据。

## 18 全屏图库

**对应：** `MemoryPhotoGallery 全屏状态`

采用深色背景、当前序号、主图和缩略图。图库只负责查看和切换照片，不混入删除、排序、同行者等编辑能力；移动端支持滑动，桌面保留方向键和 Escape。
