# Travel Memory 移动端视觉基准

本目录中的 10 张 PNG 是 Travel Memory 后续移动端页面优化的主要视觉基准，基准确认日期为 2026-07-15。

## 使用规则

- 真实业务、当前代码、数据安全和权限边界始终优先。
- 对应页面的布局、视觉层级、留白、卡片比例和移动端交互优先参考本目录 PNG。
- 设计图中不存在于当前项目的字段或功能仅代表视觉占位，不得据此直接新增业务。
- 不写死图片中的旅行、照片数量、头像、地点、时间或统计数据。
- 桌面端继续遵循现有响应式设计，不把移动端画面机械放大。

## 业务边界

- `01-trip-list`：统计和旅行内容必须来自真实接口，不写死示例数据。确认城市候选后可显示“国家 · 城市”；旧数据和手填城市只显示已有目的地。
- `02-trip-create`：复用当前真实的旅行草稿和受保护封面上传；封面、白纸表单卡片、说明条和单一移动端保存按钮按设计图组织。目的城市只使用输入与下拉候选，精确地图选点留给 Memory，不写死设计图中的城市或封面。
- `03-trip-timeline`：不增加天气等当前数据模型不存在的信息；旅行内导航保留真实页面。
- `04-trip-favorites`：作为收藏筛选的视觉参考；当前实现复用 Timeline，并由旧 `/favorites` 地址跳转到当前 Trip 的收藏筛选状态，不扩展为全局收藏中心。
- `05-trip-journey`：只展示用户原话，不自动生成或改写旅行故事。一条 Memory 始终是一站；照片按 `sortOrder` 排序，最多预览两张。横图和竖图同时存在时使用“左下横图 + 右侧竖图”，其他组合仅在右侧显示第一张，剩余照片进入统一图库。
- `06-trip-map`：图钉按 Memory 时间顺序编号；虚线表示记忆顺序，不代表真实导航路线。首次进入适配整趟旅行且不自动弹卡片；点击图钉只平移，切换日期仅为当天执行一次范围适配。路径回放开始时适配当前范围，近距离站点平滑移动，真正的远距离切换才使用短暂的缩小、移动、放大动画，并预加载下一站主图。浮层只保留设计图中的照片、时间、地点与原话层级，不增加收藏或更多操作；动态安全边距必须保证 Marker、高德版权、回放控件和横滑日期导航互不遮挡。全屏图库挂载到页面根层级，底部缩略图不得被地图浮层覆盖。无定位 Memory 时允许以 Trip 目的城市为默认中心，但不得生成虚假点位。
- `07-memory-create`：继续遵守最多 6 张照片、EXIF、地点和同行者的现有规则。
- `08-memory-detail`：分享等尚未实现的入口只作构图参考，不自动开发。
- `09-trip-recap`：只使用真实统计和 Memory 数据，不生成虚假回顾内容。
- `10-trip-companions`：当前账号从 `app_user` 读取并作为“我”置顶；其他同行人是旅行内称呼标签，不是账号，也不产生内容访问权限。页面默认不查询相关记忆，选择“我”后显示本旅行全部 Memory，选择其他同行人后再查询其关联 Memory。

## 2026-07-17 对齐实现

- 十张 PNG 继续作为核心业务页的移动端视觉基准，统一使用 `320px` 到 `430px` 的单列内容画布，并重点检查 `390×844`。
- `/trips` 在移动端使用页面内头像菜单，不再叠加桌面顶栏；账号菜单由 `UserMenu.vue` 统一维护。
- 旅行内页复用 `TripViewNav.vue` 的 5 项导航；Journey、Map、旅行回顾和同行者复用 `TripContextCard.vue`，避免各页重复实现旅行封面、标题和日期摘要。
- 旅行卡片将收藏和更多操作放在标题旁，底部固定呈现 Journey、Timeline、地图和旅行回顾四类浏览入口。
- 表单页统一使用顶部返回/草稿操作、分段卡片和底部安全区保存按钮；Memory 新增与编辑继续共享同一套表单样式。
- 视觉实现以真实照片和真实接口数据为主，不补天气、分享、虚构头像、虚构统计或设计图中的示例旅行。
- `/trips` 使用“我的旅行记忆”“新建一次旅行”和底部续写入口，并以低对比纸张纹理、邮戳线稿与柔和白纸卡片贴近 `01-trip-list.png`。
- Timeline 使用收藏筛选承接原收藏回看能力；旧收藏地址继续兼容，但不再维护重复页面结构。
- Map 使用单一恢复路线控件、编号图钉、顺序虚线、图钉安全避让和横滑日期导航；日期或图钉切换只更新地图选中状态，不把页面滚回顶部。
- 同行者页将 `app_user` 当前账号与 Trip 同行者名单分开：当前账号固定首位，名单只管理其他同行人；相关记忆在用户选择后加载，并使用紧凑横向卡片展示。

## 2026-07-28 Journey 照片预览收口

- Journey 不再根据照片总数铺开 3 到 6 张图片，避免阅读页变成照片瀑布流。
- 同时存在横图与竖图时，第一张横图作为左下辅助图，第一张竖图作为右侧主图；其他图片组合只展示排序第一张。
- 左右栏在常规手机宽度约为 `42% / 58%`，窄屏约为 `44% / 56%`；左侧横图使用 `16:9`，右侧主图保持稳定高度。
- 只有存在未展示照片时才显示“共 N 张”，点击任意预览仍从对应照片进入包含全部图片的统一图库。
- 图片方向识别完成前保留稳定占位，长地点和原话允许安全换行，不得侵入右侧图片区。
