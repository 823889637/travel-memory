# Travel Memory 工程规则

## 产品边界

- Travel Memory 不只是帮助用户记录旅行，更重要的是帮助用户多年以后重新体验一次真实发生过的旅行。
- 不自动改写、补写或生成用户原话；`content` 属于用户的原始记忆。
- Journey、Timeline 和 Map 展示真实记录，不为叙事效果虚构内容。
- 地点推荐、搜索和地图选点只提供辅助信息；不得覆盖用户已确认或手动填写的地点名称。

## 代码与接口

- 不随意修改既有接口路径、请求字段、返回结构或错误语义；兼容性扩展优先采用新增字段或新增接口。
- 不做与当前任务无关的大范围重构，不为局部功能引入大型依赖或新的状态管理方案。
- 新增数据库变更必须提供独立、可审查、可重复执行的升级 SQL；不得通过修改初始化 SQL 影响已部署数据。
- Memory 坐标在数据库统一保存为 WGS84。高德地图和 POI 服务使用的 GCJ-02 坐标必须通过统一转换链路归一化，页面不得各自实现不同规则。
- 高德 Web Service Key 只能由后端使用；前端仅使用地图 JS API 所需的 Key 与安全配置，真实 Key 和安全密钥不得提交 Git。
- 多照片仍属于同一段 Memory，不为单张照片增加独立原话、时间或地点；图片顺序和主图必须保持一致。
- Journey 中一条 Memory 始终只是一站。阅读流最多预览两张照片：横图和竖图同时存在时各取排序中的第一张，其他组合只显示第一张；未展示照片必须保留在统一图库中，不得因预览降级丢失数据或改变 `sortOrder`。
- 同行者名单中的其他人物是 Trip 内的记忆称呼，不是 `app_user`、好友或协作者。同行者页面的“我”必须来自当前登录的 `app_user`，不得在 `trip_companion` 中重复创建；Memory 只能关联本旅行的其他同行者，不能借此获得旅行访问权限。
- 自动旅行回顾只能整理现有 Trip、Memory、照片、收藏、时间和地点数据，不生成总结句，不改写用户原话。

## 数据与部署

- 禁止删除、重建或替换生产 MySQL volume。
- 禁止在需要保留数据的环境执行 `docker compose down -v` 或 `docker-compose down -v`。
- 生产 MySQL 版本变更必须先备份、核验版本和数据卷兼容性；不得原地跨大版本降级。
- `.env`、`.htpasswd`、备份、证书、私钥、真实密码和第三方 Key 不得提交 Git。
- 文件删除必须限制在配置的 uploads 根目录内，不跟随符号链接，并在删除前完成数据库引用保护和安全保留期判断。

## 账号与数据隔离

- `travel_trip.user_id` 是旅行数据的唯一归属来源；Memory、`memory_photo` 和封面通过所属 Trip 继承归属，不重复维护用户字段。
- 所有按 Trip ID、Memory ID 或照片 ID 读取、搜索、修改、删除、排序、收藏和设置封面的接口，都必须先验证当前用户拥有对应 Trip。跨用户资源统一返回 `404`，不得使用不同的 `403`、`400` 或文案泄露资源是否存在。
- 同行者查询、添加、头像更新、改名、停用和 Memory 关联也必须先验证 Trip 归属；名单管理只能创建“我”以外的同行者。Memory 提交的同行者 ID 必须全部属于同一 Trip，并通过批量查询装配，避免列表 N+1。
- 同行者页不得在初次进入时自动查询某人的相关 Memory。选择当前用户时直接使用已加载的本旅行 Memory；选择其他同行人后再调用受 Trip 归属保护的相关记忆接口。
- `/uploads/**` 不得恢复为 Spring 或 Nginx 的静态目录公开映射。新文件必须位于 `/uploads/users/{userId}/...`，读取和创建 Memory 引用时都要校验当前用户、规范化路径、真实文件和符号链接；旧上传文件仅兼容初始管理员。
- 注册默认关闭，邀请码只从环境变量读取，不能写入日志、接口响应、前端构建产物或 Git。管理员只能管理账号，不得绕过旅行数据的归属校验。
- Session Cookie 使用 `HttpOnly` 与 `SameSite=Lax`；生产 HTTPS 启用后设置 `APP_SESSION_COOKIE_SECURE=true`。登录、注册和修改密码必须轮换 Session ID，退出登录必须使当前 Session 失效；账号禁用、密码修改或管理员重置密码后，旧 Session 必须在下一次请求被拒绝。
- 所有状态变更接口继续使用 CSRF 防护。前端先请求 `/api/auth/csrf`，再由 Axios 回传 `X-XSRF-TOKEN`；不得为方便调试关闭 CSRF。
- 生产环境首次启用孤儿图片清理必须使用 dry-run；确认候选统计正确后，才可单独评估真实删除。

## 验证要求

- 前端修改后执行 `npm run build`。
- 后端修改后执行 `mvn test`，或至少完成可验证的编译；涉及接口和坐标转换时应补充针对性测试。
- 上传、多照片、Timeline、Journey、Map、地点搜索与选点是核心回归链路；涉及其依赖配置时必须回归检查。
