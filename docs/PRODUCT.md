# Travel Memory 产品状态

Travel Memory 保存真实发生过的旅行记忆，帮助用户多年以后重新体验一段旅行，而不只是浏览照片或记录流水账。照片、用户原话、时间和地点共同构成一段 Memory；系统不自动改写用户原话。

## 已完成 V1

- Trip：创建、查看、编辑和删除旅行。
- Memory：新增、编辑、删除，记录原话、时间、地点名称和坐标。
- Timeline：按日期浏览、搜索、收藏和必要的管理操作。
- 收藏筛选：Timeline 可切换为只浏览当前旅行中已收藏的 Memory，并保持日期分组；旧 `/favorites` 地址兼容跳转到该筛选状态。
- Journey：按日期和站点回放旅行，保持纯阅读模式；每段 Memory 最多预览两张照片，完整照片仍通过统一图库浏览。
- Map：基于高德真实地图按时间顺序展示编号图钉，并用虚线表达 Memory 先后关系；点击图钉可查看照片、时间、国家/城市/地点和用户原话。日期使用地图下方的横向滑动标签；点击图钉只平移，日期聚焦和开始回放分别进行一次范围适配，远距离回放采用短暂的缩小、移动、放大过渡并预加载下一站主图。动态安全边距避免 Marker、Memory 卡片、回放控制、日期导航和高德版权相互遮挡；全屏图库完整覆盖地图浮层且保留底部照片切换。没有坐标的记忆不会生成图钉，连线不代表导航路线或真实轨迹。

## 已完成 V1.1

- 多照片 Memory：同一段记忆最多 6 张照片，支持排序、主图同步、删除与统一图库浏览；旧单图数据保持兼容。
- 图片 EXIF 时间和 GPS 解析，以及浏览器当前位置。
- 坐标约定：数据库统一保存 WGS84；高德地图展示、POI 搜索和地图点击使用 GCJ-02 时，由前后端既有转换链路归一化为 WGS84。
- 高德逆地理编码和地点名称候选推荐；用户确认后才使用推荐名称。
- 地点搜索与地图选点：可搜索高德 POI、在地图点击选点、使用浏览器当前位置，并始终允许用户保留或修改自己的地点描述。
- 旅行目的城市定位：创建和编辑旅行时通过输入关键词选择城市候选；确认候选后保存解析出的国家、城市名称和 WGS84 城市中心坐标。旅行首页可显示“国家 · 城市”；旧数据或手工填写时仍安全回退为只显示城市。没有带坐标的 Memory 时，旅行地图以目的城市作为默认中心；国外城市仍允许只填写名称。
- 旅行封面管理：创建旅行时可上传受保护封面，也可从本旅行已有的 Memory 照片中设置或取消显式封面；未设置时自动使用第一张照片。暂不支持图片裁切。
- Docker Compose 与阿里云 ECS 部署。
- Nginx Basic Auth 临时访问保护、安全 Nginx 覆盖和 `/healthz`。
- MySQL 与 uploads 本地备份脚本。
- 孤儿图片清理能力：默认关闭并使用 dry-run，仅处理超过保留期且未被 Memory、多照片或 Trip 封面引用的 uploads 文件；不等同于云端图片管理。
- 第一版账号与数据隔离：受控邀请码注册和管理员账号管理、Spring Security Session 登录、首次改密和账号锁定；Trip 按用户归属，Memory、照片与封面继承该归属，管理员不自动查看其他用户的私人旅行。
- 私有图片访问：新上传图片按用户目录保存，`/uploads/**` 经登录和归属校验读取；跨用户资源统一按不存在处理。
- 会话安全：登录、注册和修改密码会轮换 Session ID；禁用账号、修改密码或管理员重置密码后，旧 Session 会在下一次请求失效。

## V1.2 本地开发完成，待浏览器与上线验收

- 单趟旅行回顾：基于现有 Trip 和 Memory 自动整理旅行摘要、每日代表片段、常出现地点与收藏回忆，不新增回顾表，不生成或改写用户原话。
- 同行的人：页面中的“我”来自当前登录的 `app_user`，固定显示在同行人列表首位，并代表当前旅行的全部 Memory；不在 `trip_companion` 中重复创建自己。
- 其他同行人：每趟旅行可维护“我”以外的同行者称呼，每条 Memory 可记录当时在场的人；这些同行者只是记忆上下文，不对应系统账号，也不获得查看或编辑旅行的权限。
- 相关记忆：进入页面时不自动查询。用户选择“我”后浏览本旅行全部 Memory；选择其他同行人后，才查询并横向展示与其关联的照片、原话、地点和时间。
- 同行者管理：新增时只填写名字，之后可在名单中添加或更换头像、改名、停用；不提供“这是我”选项。
- 同行者停用只影响后续选择，历史 Memory 已记录的同行信息继续保留。
- 多用户错误边界继续使用原有 `Result` JSON，同时让业务 `400`、跨用户 `404` 和服务错误返回对应的真实 HTTP 状态。

产品坚持照片和用户原话优先。Journey 用于重新体验旅行，不负责生成或改写故事，也不把多照片铺成瀑布流；地点服务只辅助定位，不替代用户对地点的记忆。
