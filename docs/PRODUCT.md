# Travel Memory 产品状态

Travel Memory 保存真实发生过的旅行记忆，帮助用户多年以后重新体验一段旅行，而不只是浏览照片或记录流水账。照片、用户原话、时间和地点共同构成一段 Memory；系统不自动改写用户原话。

## 已完成 V1

- Trip：创建、查看、编辑和删除旅行。
- Memory：新增、编辑、删除，记录原话、时间、地点名称和坐标。
- Timeline：按日期浏览、搜索、收藏和必要的管理操作。
- 收藏回看：只浏览当前旅行中已收藏的 Memory，并按日期分组。
- Journey：按日期和站点回放旅行，保持纯阅读模式。
- Map：基于高德真实地图展示有坐标的记忆点；点击点位可查看对应记忆。没有坐标的记忆不会显示在地图中，不包含导航、路线规划或轨迹回放。

## 已完成 V1.1

- 多照片 Memory：同一段记忆最多 6 张照片，支持排序、主图同步、删除与统一图库浏览；旧单图数据保持兼容。
- 图片 EXIF 时间和 GPS 解析，以及浏览器当前位置。
- 坐标约定：数据库统一保存 WGS84；高德地图展示、POI 搜索和地图点击使用 GCJ-02 时，由前后端既有转换链路归一化为 WGS84。
- 高德逆地理编码和地点名称候选推荐；用户确认后才使用推荐名称。
- 地点搜索与地图选点：可搜索高德 POI、在地图点击选点、使用浏览器当前位置，并始终允许用户保留或修改自己的地点描述。
- 旅行封面管理：可从本旅行已有的 Memory 照片中设置或取消显式封面；未设置时自动使用第一张照片。暂不支持独立上传或裁切封面。
- Docker Compose 与阿里云 ECS 部署。
- Nginx Basic Auth 临时访问保护、安全 Nginx 覆盖和 `/healthz`。
- MySQL 与 uploads 本地备份脚本。
- 孤儿图片清理能力：默认关闭并使用 dry-run，仅处理超过保留期且未被 Memory、多照片或 Trip 封面引用的 uploads 文件；不等同于云端图片管理。
- 第一版账号与数据隔离：受控邀请码注册和管理员账号管理、Spring Security Session 登录、首次改密和账号锁定；Trip 按用户归属，Memory、照片与封面继承该归属，管理员不自动查看其他用户的私人旅行。
- 私有图片访问：新上传图片按用户目录保存，`/uploads/**` 经登录和归属校验读取；跨用户资源统一按不存在处理。
- 会话安全：登录、注册和修改密码会轮换 Session ID；禁用账号、修改密码或管理员重置密码后，旧 Session 会在下一次请求失效。

## V1.2 本地开发完成，待浏览器与上线验收

- 单趟旅行回顾：基于现有 Trip 和 Memory 自动整理旅行摘要、每日代表片段、常出现地点与收藏回忆，不新增回顾表，不生成或改写用户原话。
- 同行的人：每趟旅行可维护同行者称呼，每条 Memory 可记录当时在场的人；同行者只是记忆上下文，不对应系统账号，也不获得查看或编辑旅行的权限。
- 同行者停用只影响后续选择，历史 Memory 已记录的同行信息继续保留。
- 多用户错误边界继续使用原有 `Result` JSON，同时让业务 `400`、跨用户 `404` 和服务错误返回对应的真实 HTTP 状态。

产品坚持照片和用户原话优先。Journey 用于重新体验旅行，不负责生成或改写故事；地点服务只辅助定位，不替代用户对地点的记忆。
