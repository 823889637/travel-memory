# Travel Memory UI Guideline

## 设计目标

Travel Memory 不是旅行攻略、相册管理软件或后台管理系统。它是一册旅行回忆录：用户打开页面时，应感到自己正在重新体验一次旅行，而不是管理旅行数据。

所有设计围绕旅行、照片、故事和回忆展开。照片和用户原话优先，操作保持克制，移动端优先。

## 视觉原则

- 简洁、温暖、克制、沉浸，保留足够留白。
- Timeline 的照片应完整显示，不拉伸、不明显裁切；桌面端保持稳定的照片与文字列，移动端自然改为上下布局。
- Journey 必须自然支持横图、竖图和方图。阅读流中的照片是紧凑预览，可使用 `object-fit: cover` 建立稳定构图；点击后由统一图库完整展示原图，不修改或保存裁切结果。
- 多照片以少量代表照片和总数提示保持浏览节奏；点击任意预览进入统一图库，而不是在阅读页堆叠照片瀑布流。
- 不做后台管理感、密集表格、炫技动效或让按钮压过照片和原话的布局。
- 使用清晰的文字层级、轻阴影、适度圆角和可访问的颜色对比。

## 页面职责

### 列表

旅行列表用于进入不同旅行，突出封面、标题、目的地和时间，不承担复杂编辑工作。移动端标题使用“我的旅行记忆”，只保留一个清晰的新建入口；列表末尾使用“下一段旅程，正在路上”的轻量续写入口。卡片中的地点、日期和真实统计使用统一线性图标，背景和阴影保持接近白纸而不是厚重面板。

### 表单

创建和编辑页面用于低成本留下或修正记忆。字段保持必要，照片、原话、时间和地点优先，错误提示直接且温和。

地点搜索和地图选点属于表单的辅助流程：在独立弹窗或抽屉内维护临时选择，只有用户确认后才回填表单。官方地点名称是建议，不应覆盖用户的自定义地点描述。

Trip 的目的城市与 Memory 的精确地点分开处理。创建和编辑旅行时只使用城市输入与下拉候选，不提供地图选点；确认候选时同时保存解析出的国家和 WGS84 城市中心，旅行列表优先显示“国家 · 城市”。城市坐标只决定旅行地图的默认视野，不替代每条 Memory 自己的时间和地点。用户手动修改城市名称后必须同时清除旧国家和坐标，避免展示错误组合。精确地图选点只属于 Memory 表单。

旅行创建与编辑复用相同的封面和基础字段视觉：封面独立展示，标题、城市、日期、描述与笔记放在单一白纸卡片中。移动端底部只保留一个保存主操作，返回按钮承担取消；编辑页的封面替换和恢复自动封面均在保存修改后生效，取消编辑不得提前改变原封面。

### Timeline

Timeline 是原始记忆记录页，按日期和时间组织 Memory，支持搜索、收藏筛选、图库及必要的次级管理操作。原话和地点是信息主体，收藏与更多操作应保持弱化；日期只在分组标题出现，卡片时间轴只显示时分。收藏筛选属于 Timeline 的浏览状态，不再维护一套独立的收藏列表布局。

### Journey

Journey 是回放页，按日期和站点重新走过旅行。它强调地点、照片、原话和时间顺序；“下一站”仅作轻量分隔，不应出现编辑、删除、收藏或搜索等管理动作。

一条 Memory 只形成一个站点，不因照片数量拆成多个站点。照片按 `sortOrder` 排序，Journey 最多预览两张：

- 同时存在横图和竖图时，排序中最先出现的横图放在左侧文字下方，最先出现的竖图作为右侧主图。
- 其他组合，包括全横图、全竖图、全方图以及方图混合，只在右侧显示排序第一张照片。
- 预览未覆盖全部照片时，仅在右侧主图显示“共 N 张”；全部照片均已预览时不显示数量角标。
- 左侧文字与右侧图片保持稳定双栏，长英文和数字必须安全换行；小屏不得让图片遮挡地点或原话。
- 图片方向识别完成前使用稳定占位，避免页面先平铺照片再跳成双栏。

### Map

Map 用真实地图回答记忆发生在哪里。它以按时间排序的编号图钉、记忆顺序虚线、路径回放和当前选中的 Memory 卡片为核心，但不承担导航或路线规划；虚线只表达 Memory 先后，不代表真实行车、步行或交通路线。没有坐标或有效记录时间的记忆应得到温和说明。浮层只展示序号、地点、首张照片、时间、国家/城市/地点和用户原话，不加入收藏、更多操作、经纬度或重复记录时间。

地图页不叠加高德缩放工具栏和当前位置控件，只保留“恢复完整路线”和选中点放大等明确控件；缩放和拖动使用地图原生手势。首次进入适配整趟旅行，点击图钉只平移，切换日期仅为当前日期执行一次范围适配。开始回放时先适配当前范围，近距离站点平滑平移；真正的远距离切换才使用“缩小、移动、放大”的短动画，并在更新卡片前预加载下一站主图。新卡片在对应图钉进入浮层外的安全区域后再显示，避免出现先遮挡再移开的跳动。日期导航位于地图下方，仅使用可横向滑动的自然日标签，不使用日期下拉框；更新 URL 中的选中 Memory 时必须保留页面当前滚动位置。

地图上的卡片、回放控件和日期导航属于画布浮层，必须使用动态安全边距避免遮挡 Marker。全屏图库必须挂载到页面根层级而不是地图卡片内部，完整覆盖地图浮层；底部缩略图需要同时避让移动端安全区，关闭图库后恢复页面滚动和原有地图选中状态。

当整趟旅行尚无定位 Memory 时，可使用 Trip 的目的城市中心建立空间上下文，但不得把城市中心伪装成 Memory。地图展示页不直接编辑数据，坐标修正通过 Memory 表单中的选点流程完成。地图应保留高德要求的 Logo、版权与审图信息，不用 CSS 隐藏。

### 同行的人

同行者页面用于回看“和谁一起经历了哪些片段”，阅读优先于名单管理。当前登录账号来自 `app_user`，作为“我”固定放在第一行；其他同行人来自当前 Trip 的同行者名单，不能把两种数据来源混为一张账号表或一张同行者表。

页面进入时不自动查询相关记忆。标题区使用轻量自定义选择器：选择“名字（我）”时显示本旅行全部 Memory，选择其他同行人后才请求其关联 Memory。结果采用紧凑横向卡片，依次呈现首张照片、用户原话、地点、完整时间和照片数量，不按日期重新铺成 Timeline。

“管理名单”是页面末尾的次级入口。新增同行人时只输入名字，不提供“这是我”选项，也不要求先上传头像；头像应在已有同行者行中补充或更换。改名、停用和重新启用集中在弹窗或移动端底部抽屉中，历史 Memory 关联不因停用而消失。

## 布局与交互

- 不要求所有页面使用相同的 Header、Summary、Timeline 或 FAB 组合。
- 页面结构应服务于页面职责：列表便于扫描，表单便于填写，Timeline 体现连续时间，Journey 体现沉浸回放，Map 体现空间关系。
- 旅行内一级导航固定为时间线、旅程回放、地图、旅行回顾和同行的人 5 项。收藏属于 Timeline 的筛选状态，不再占用独立导航项。
- 普通移动端阅读页右上角使用统一账号头像；创建或编辑页面存在“保存草稿”等明确任务操作时，保留任务文字按钮，不强制替换为头像。

## 移动端视觉基准

- `docs/mobile-design/设计图` 中的十张 PNG 是核心页面的移动端布局基准，真实业务与权限边界优先于示例内容。
- 移动端页面内容宽度上限为 `430px`，常用水平留白为 `16px` 到 `18px`；卡片、地图画布和封面必须在 `390×844` 下无横向溢出。
- 页面标题使用适度的衬线字体建立回忆录气质，表单、按钮和辅助信息继续使用系统无衬线字体，不能让装饰文字降低可读性。
- 旅行上下文、账号菜单、旅行内 5 项导航必须复用共享组件，不允许各页面重新制作尺寸不同的图标、头像或标题条。
- 固定在底部的保存操作必须包含 `safe-area-inset-bottom`，更多菜单和账号菜单不得越过视口边缘。
- 设计图中的天气、分享、虚构数据和虚构人物不得作为纯视觉填充进入真实页面。
- 删除和高风险操作放在次级入口或确认流程中，不作为主视觉重点。
- 图片需要准确的 `alt` 文本；触控目标保持足够大小；加载状态优先使用稳定占位，避免页面跳动。

## 最终原则

每次 UI 变更前，确认它是否更像旅行回忆、是否突出照片和时间、是否减少操作负担、是否适配移动端。若页面更像管理系统，应重新设计。
