# Travel Memory UI Guideline

## 设计目标

Travel Memory 不是旅行攻略、相册管理软件或后台管理系统。它是一册旅行回忆录：用户打开页面时，应感到自己正在重新体验一次旅行，而不是管理旅行数据。

所有设计围绕旅行、照片、故事和回忆展开。照片和用户原话优先，操作保持克制，移动端优先。

## 视觉原则

- 简洁、温暖、克制、沉浸，保留足够留白。
- 普通列表和摘要卡片可使用统一的图片裁切比例，以保证浏览节奏稳定。
- Journey 必须自然支持横图、竖图和方图；竖图可使用同一张图的模糊背景承托，不应被强行裁切为横图。
- 不做后台管理感、密集表格、炫技动效或让按钮压过照片的布局。
- 使用清晰的文字层级、轻阴影、适度圆角和可访问的颜色对比。

## 页面职责

### 列表

旅行列表用于进入不同旅行，突出封面、标题、目的地和时间，不承担复杂编辑工作。

### 表单

创建和编辑页面用于低成本留下或修正记忆。字段保持必要，照片、原话、时间和地点优先，错误提示直接且温和。

### Timeline

Timeline 是原始记忆记录页，按时间组织 Day 和 Memory，支持浏览、搜索、收藏及必要的管理操作。

### Journey

Journey 是回放页，按 Day 和 Stop 重新走过旅行。它强调照片、原话和时间顺序，不应堆叠编辑、删除或搜索等管理动作。

### Map

Map 是基础空间视图，用于回答记忆发生在哪里。当前不是地图 SDK、导航或路线规划功能；没有坐标的记忆应得到温和说明。

## 布局与交互

- 不要求所有页面使用相同的 Header、Summary、Timeline 或 FAB 组合。
- 页面结构应服务于该页面职责：列表便于扫描，表单便于填写，Timeline 体现连续时间，Journey 体现沉浸回放，Map 体现空间关系。
- 删除和高风险操作放在次级入口或确认流程中，不作为主视觉重点。
- 图片需要准确的 `alt` 文本；触控目标保持足够大小；加载状态优先使用骨架屏或稳定占位。

## 最终原则

每次 UI 变更前，确认它是否更像旅行回忆、是否突出照片和时间、是否减少操作负担、是否适配移动端。若页面更像管理系统，应重新设计。
